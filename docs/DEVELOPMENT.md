# Maintainer guide

These instructions are for the owner and authorized contributors. They do not grant distribution or hosting rights; see LICENSE.

## Requirements

Node.js 22.13 LTS or 24+ and npm. Blender is needed only to regenerate GLB assets. Recording additionally requires Chrome with hardware graphics acceleration and FFmpeg/FFprobe on PATH.

## Local development

```sh
npm ci
npm run dev
```

Vite displays the local URL. Saves use `baguette-tycoon-v3`; test with a separate browser profile to keep personal progress intact.

## Checks

```sh
npm run lint
npm test
npm run build
npm run test:smoke
```

Lint checks JavaScript, comments and long dash characters in owned text sources. The unit check covers offline income limits. Browser smoke checks normal input, resizing, capture timing and save isolation. Both production editions must build before a release.

`tools/check-layout.mjs` and `tools/review-layout.mjs` expect a development server on port 5194 and produce ignored screenshots in `tmp/`. They inspect the expanded layout; the access check walks with collisions enabled. Python simulation helpers require the Python Playwright package, use `BT_PORT` (default 4173) and expect a running game server.

## Local integration settings

Optional host services are configured in the ignored `.env.local` file. `.env.example` lists the empty configuration keys. Without local values, the game uses browser storage and disables external services. Never commit local service configuration.

## Production output

- `npm run build:full`: Full build in `dist/`.
- `npm run build:basic`: advertising-disabled build in `dist-basic/`.
- `npm run build`: both editions.

Keep `index.html` at the archive root. PowerShell release packaging:

```powershell
Compress-Archive -Path dist/* -DestinationPath baguette-tycoon-full.zip -Force
Compress-Archive -Path dist-basic/* -DestinationPath baguette-tycoon-basic.zip -Force
```

Build directories and archives are ignored by Git. Never commit credentials or local progress.

## Architecture

`src/main.js` coordinates the simulation, unlocks, saves and UI actions. `products.js` and `stations.js` define production and service stations. `world.js` owns rooms, navigation and collision bounds; `layout.js` defines the architectural grid. `character.js` handles characters and item stacks. `economy.js` calculates bounded offline income. `models/` contains reusable procedural models. `hud.js`, `icons.js`, `i18n.js` and `style.css` provide interface and translations. `sdk.js` wraps optional host services with local fallback. `juice.js` manages animation effects, input and audio.

Keep all six languages in `src/i18n.js` in sync. Full and Basic share the same save schema and game rules; Basic disables advertising through the build mode.

## Recording

```sh
npm run marketing:preview
npm run marketing:record
npm run marketing:verify
```

The recording server instruments `main.js` in memory. Its scenario lives in `tools/marketing/recording.js`; it is not part of the production bundle. No game save is changed. Capture runs at a manual 1/60-second step and rejects source changes during a take.

Final videos are written to `marketing/videos/`. Working material goes to `tmp/marketing/`. `--format=landscape`, `--format=portrait` and `--resume` can be passed after `--` to `npm run marketing:record`. Resume only reuses frames with the same source fingerprint.

The final videos predate this structural cleanup. Verify their media properties independently; a new capture receives a new source fingerprint even when the visible gameplay is unchanged.

## Asset sources

Blender scripts are in `tools/models/`. Nature conversion requires separately obtained Quaternius source assets. `node tools/make-register.mjs` regenerates only the original register sound and requires FFmpeg. Approved cover artwork is not regenerated by the build.
